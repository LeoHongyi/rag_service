# PRODUCT.md

## 产品名称

FBA Agentic RAG 知识库服务

## 产品简介

本项目是一套面向应用开发者的 RAG 后端服务。用户可以创建知识库、上传文档并等待系统完成索引，然后通过混合检索或问答接口获取带来源引用的结果。复杂、模糊或需要多步检索的问题可由有界 Agentic RAG 自动改写、拆解、评估证据并修正答案。

第一版专注 RAG 核心链路和受控 Agentic 检索，不包含通用聊天产品、开放式 Agent、前端控制台、支付或多媒体生成。

## 当前成熟度

截至 2026-07-21，产品处于可运行基线阶段：知识库、异步文档索引、DashScope Embedding、PostgreSQL 混合检索、带引用问答和单步有界 Agent 路径已经完成端到端验证。索引任务的超时有限重试、重试耗尽、Worker 中断和 Beat 恢复也已在隔离 Redis Broker 与受控模型端点下完成真实进程故障注入验证。

以下能力仍是目标，不是现状：真正的多步 Agentic RAG、结构感知父子切片、中文词法检索、Rerank 和 S3/MinIO。离线评测框架、索引 provenance、Outbox 和删除补偿已具备最小实现；真实 Service 执行器与合成 Golden 阈值门禁也已实现，但 50 条候选样本仍未绑定真实语料或经领域人工审批，不能对外宣称已经拥有领域质量基线或真实发布阈值。

## 产品文档使用边界

本文定义产品意图、范围和验收语言，不替代运行事实。实现成熟度以 `session-handoff.md` 的证据为准，技术实现、数据契约和部署细节以 `docs/ARCHITECTURE.md` 为准。任何改变用户可感知行为的功能，都必须同时更新本文的范围、流程或验收标准；仅限内部重构则不应制造虚假的产品变更。

## 产品目标与成功指标

产品优先解决“答案是否来自正确资料”，再优化自动化程度。每次发布都需要与固定基线比较。

核心成功指标：

- **检索质量**：领域评测集报告 Recall@5、Recall@20、MRR 或 nDCG，并按事实、精确术语、多跳和拒答样本分组。
- **生成质量**：报告答案正确性、groundedness、引用准确率、引用召回率和拒答准确率。
- **可靠性**：文档任务终态可解释，重复投递不产生重复切片，模型和 Broker 故障可恢复。
- **性能**：分别记录索引吞吐、检索 P50/P95、问答 P50/P95、模型 Token 与单请求估算成本。
- **安全**：越权检索率和无效引用率必须为 0；提示注入样本不能扩大工具或数据权限。

## 目标用户

- 需要为内部资料、产品文档或客服知识构建智能检索的开发团队。
- 需要通过 REST API 将知识库问答接入现有网站、应用或 Agent 的后端开发者。
- 需要管理私有知识库和公共知识库的系统管理员。

## 核心问题

项目解决以下问题：

- 文档分散，依赖关键词搜索难以找到语义相关内容。
- 大模型无法直接掌握用户的私有或最新资料。
- 文档处理、切分、向量化和检索流程难以稳定编排。
- 大模型回答缺少来源，用户无法核验答案依据。
- 知识库之间需要严格的数据隔离和访问控制。
- 单次向量 Top-K 难以处理精确术语、多跳问题、模糊问题和证据不足场景。
- 复杂 Agent 容易产生无限循环、成本失控、错误工具调用和间接提示注入风险。

## 用户角色

### 普通用户

- 创建、查看、修改和删除自己的知识库。
- 上传、查看和删除自己知识库中的文档。
- 查询文档索引状态和失败原因。
- 在有权访问的知识库中执行检索和问答。
- 读取管理员设为公开的知识库。

### 管理员

- 拥有普通用户的全部能力。
- 管理所有知识库和文档。
- 将知识库设置为公开或私有。
- 查看全局索引状态与基础统计数据。

## 核心用户流程

### 创建和索引知识库

1. 用户创建知识库，填写名称和可选描述。
2. 用户上传 `.txt`、`.md`、`.docx` 或带文本层的 `.pdf` 文件。
3. 系统保存原始文件和文档元数据，将状态设为“排队中”。
4. 后台任务解析文本、清洗内容、切分文本并生成向量。
5. 索引成功后，文档状态变为“可用”；失败时记录安全且可读的错误原因。
6. 用户可查询文档状态、预览解析文本和查看切片。

### 混合检索

1. 用户选择一个或多个有权访问的知识库并输入问题。
2. 系统同时生成查询向量和关键词查询。
3. 系统在授权知识库范围内执行稠密检索与 PostgreSQL 全文检索。
4. 系统使用 RRF 融合候选，并按配置执行重排、去重和父级上下文扩展。
5. 系统返回融合得分、可选重排得分、切片内容、文档名称和定位信息。

### RAG 问答

1. 系统先执行语义检索。
2. 系统将命中的切片组织成受长度限制的上下文。
3. 大模型仅基于问题和检索上下文生成答案。
4. 系统返回答案与结构化来源。
5. 当资料不足时，答案必须明确说明无法从当前知识库确定，不得伪造来源。

### Agentic RAG 问答

本节描述目标流程。当前代码只实现模式选择、一次只读检索和有界停止。

1. 用户通过 `mode=auto` 或 `mode=agentic` 提交问题；`auto` 默认优先低延迟基础 RAG。
2. 路由器使用严格结构化输出判断问题是否需要改写、拆解或迭代检索。
3. 系统最多生成 3 个可独立检索的子问题，并行调用只读知识库检索工具。
4. 系统融合、重排并评估证据相关性与充分性。
5. 证据不足时最多改写并重试 2 轮；达到预算后停止并返回“资料不足”。
6. 系统基于证据生成答案，再执行一次引用与事实支撑检查。
7. 检查失败时最多修复答案 1 次；服务端最终验证所有引用确实来自本次授权检索结果。
8. 响应返回答案、来源、实际模式、执行状态、检索轮数和脱敏后的诊断摘要。

## 知识库功能

第一版支持：

- 创建知识库。
- 分页查询用户可访问的知识库。
- 查看知识库详情和文档、切片数量。
- 修改名称、描述和公开状态。
- 删除知识库及全部关联数据。
- 区分私有知识库和公共知识库。

知识库名称不能为空。同一所有者下是否允许重名由实现阶段通过唯一约束明确，第一版默认不允许同名。

## 文档功能

第一版允许的文件类型：

- `.txt`
- `.md`
- `.docx`
- `.pdf`（仅带可提取文本层，不含 OCR）

默认单文件上限为 20 MB，可通过配置降低，不允许在运行时任意扩大。

文档状态包括：

- `PENDING`：已保存，等待后台任务。
- `PROCESSING`：正在解析、切分或向量化。
- `READY`：索引完成，可用于检索。
- `FAILED`：处理失败，可查看错误摘要并重试。
- `DELETING`：正在清理关联数据，不可参与检索。

同一知识库中默认不允许上传同名的有效文档。用户需要先删除旧文档，或在后续版本引入文档版本能力。

## 文本切分要求

- 切分优先保持段落和语义边界。
- 默认切片长度与重叠长度必须可配置。
- 空文本、仅空白文本和无法解析出正文的文件不能进入向量化。
- 每个切片记录顺序、内容、字符数、Token 估算值和来源文档。
- 同一文档重新索引时不得产生重复的有效切片。
- 保留标题层级、章节路径、页码或段落位置等可获得的结构元数据。
- 小切片用于召回，命中后可扩展到父章节或相邻切片用于生成。
- 用于 Embedding 和关键词检索的文本可以增加简短上下文前缀，但原始切片内容必须独立保存。
- 默认上下文前缀由文件名、标题路径和父章节摘要确定性生成；LLM 上下文化只作为评测通过后的可选索引策略。

## 检索要求

- 默认返回 5 条结果，`top_k` 范围为 1 到 20。
- 只检索状态为 `READY` 的文档。
- 必须在数据库查询阶段限制授权知识库范围，不能先全局检索再由应用层过滤。
- 返回结果包含知识库 ID、文档 ID、文档名、切片 ID、切片序号、内容和相关度。
- 可配置最低相似度；低于阈值的结果不进入问答上下文。
- 相同文档的大量相邻切片应受数量限制，避免单一文档淹没其他来源。
- 默认采用 PostgreSQL 内的稠密向量 + 全文关键词混合检索，不新增独立搜索服务。
- 两路候选使用 Reciprocal Rank Fusion（RRF）合并，不能直接比较未校准的 BM25/FTS 分数与余弦分数。
- 候选集可由 Cross-Encoder 或供应商 Rerank API 重排；重排失败时降级到 RRF，不阻断问答。
- 中文关键词检索需要确定性分词，并在索引与查询两侧使用相同分词版本。
- 检索质量必须使用固定数据集评估 Recall@K、MRR/nDCG 或 Context Precision，不能只依赖人工试问。

## Agentic 编排要求

- `basic`：固定执行“混合检索 -> 可选重排 -> 生成 -> 引用校验”。
- `agentic`：固定执行有界状态图，允许查询改写、问题拆解、证据评估和答案修复。
- `auto`：先判断复杂度，简单事实问题走 `basic`；模糊、多跳或首次证据不足时升级为 `agentic`。
- 图节点和条件边必须在代码中显式定义，不使用允许模型自由选择任意工具的开放式 ReAct 循环。
- 工具仅允许搜索授权知识库、读取命中切片的父级上下文和读取安全元数据。
- 默认预算：最多 3 个子问题、6 次工具调用、2 轮检索、1 次答案修复、30 秒总时限。
- 任一节点超时、结构化输出失败或预算耗尽时，应安全降级到已有证据生成或明确拒答。
- Agent 不具备写数据库、删除文件、读取对象存储任意键、访问外网或执行代码的能力。

## 问答要求

- 支持从一个或多个知识库构建上下文。
- 返回完整答案，不在第一版承诺 SSE 流式输出。
- 返回实际参与生成的结构化来源。
- 上下文大小、最大输出 Token 和温度可配置。
- 模型服务失败不得破坏已存储的索引数据。
- 日志不得记录 API Key、完整私有文档或未经处理的模型请求体。
- 答案中的每条引用必须映射到本次实际检索到的 `document_id + chunk_id`。
- 对关键事实进行支撑检查；无法被来源支持的陈述必须删除、改写为不确定表述或触发拒答。
- 检索文本只作为参考资料，文档内诸如“忽略系统指令”“调用工具”等内容不得作为可执行指令。

## 权限规则

- 私有知识库仅所有者和管理员可读写。
- 公共知识库允许已认证用户读取，只有所有者或管理员可修改。
- 上传、删除、重新索引和修改公开状态均属于写操作。
- API 返回 404 时应避免泄露用户无权访问的资源是否存在。
- 后台任务必须携带并校验知识库、文档关系，不能绕过业务层约束。

## 非功能要求

- API 使用统一响应结构和明确的业务错误码。
- 文档处理使用后台任务，上传接口应快速返回任务状态。
- 同一个文档任务可安全重试，不产生重复切片。
- 服务重启后任务和文档状态可恢复或被重新调度。
- 关键操作具有 Trace ID 和结构化日志。
- 核心接口具备权限、异常、幂等和边界测试。
- 基础 RAG 和 Agentic RAG 分别记录端到端延迟、模型调用次数、Token 和估算成本。
- 每次 Agentic 运行具有 Trace ID 和节点级轨迹，但默认不持久化完整问题、上下文和答案。
- Agentic 路径必须配置并发、递归、工具调用和成本硬上限。

## 质量评测要求

- 建立按业务领域分层的版本化评测集，包含问题、参考答案、相关文档/切片和期望路由。
- 检索指标：Recall@K、MRR/nDCG、Context Precision、Context Recall。
- 生成指标：Faithfulness/groundedness、Answer Relevancy、正确性、拒答准确率。
- 引用指标：Citation Precision、Citation Recall、无效引用率。
- Agent 指标：路由准确率、工具调用准确率、目标完成率、平均迭代次数、循环/超时率。
- 系统指标：P50/P95 延迟、Token、模型调用次数、单请求估算成本和失败率。
- 上线门槛：Agentic 模式必须在目标复杂问题集上显著优于 `basic` 基线，并且延迟和成本处于产品预算内。
- LLM-as-judge 指标只作为辅助信号，关键版本必须抽样进行人工核验。
- 每个新 feature 必须在实现前定义测试矩阵，并在合并前附带测试命令、结果、数据集版本和相对基线变化。
- 可确定的权限、引用 ID、Schema、状态机、预算和数据库副作用使用代码断言；不得交给 LLM 评分。
- 生产失败样本经过脱敏后进入回归集，形成“线上发现 → 离线复现 → 修复 → 回归”的闭环。

## 近期产品路线图

### P0：建立可量化的可信基线

- `implemented`：版本化 JSONL Schema、Recall@5/20、MRR、nDCG@20、引用 Precision/Recall、拒答准确率与 P50/P95 延迟报告。
- `implemented`：50 条覆盖六类风险的候选审阅队列；只有 `review_status=approved` 才能作为 CI 质量数据集。
- `implemented`：GitHub Actions 运行 Ruff、Mypy、核心测试、Alembic 升级/降级与 Golden 离线报告。
- `implemented`：不可变 `rag_index_profile` 记录 Parser、Chunker、Tokenizer、Embedding 模型/维度与 FTS 配置。
- `implemented`：文档索引通过事务内 Outbox 写入，独立 Celery Dispatcher 在提交后投递。
- `implemented`：真实 Service 离线执行器、版本化阈值比较和合成 Golden 阈值门禁；删除通过 Outbox 进入 `DELETING` 后异步清理，失败任务由定时修复重新投递。
- `planned`：由领域负责人提供并完成 50 到 100 条真实语料的绑定与人工审批，再由集成执行器产生真实服务结果并冻结业务发布阈值。

### P1：提升检索与文档质量

- 引入结构化文档中间表示，保留标题、表格、页码、段落和来源定位。
- 实现父子切片和相邻窗口扩展；分别保存召回文本与生成上下文。
- 为中文建立一致的索引/查询分词策略，保留精确标识符检索。
- 接入 `qwen3-rerank`，只在评测显示收益且 P95/成本可接受时默认启用。
- 配置 pgvector filtered ANN iterative scan，验证权限过滤后的召回完整性。

### P2：实现可解释的多步 Agentic RAG

- 用结构化路由替换“问题长度大于 80 字符”的启发式规则。
- 增加查询规范化、最多 3 个子问题、并行检索、证据充分性判断和一次修复。
- 保存脱敏节点轨迹，评估 Route Accuracy、Tool Accuracy、循环率和预算停止率。
- 使用最小高信号上下文，避免把所有候选无差别放入模型上下文。

### Research：评测触发的高级检索

- Late Chunking：只在跨段上下文丢失成为主要错误来源时实验。
- ColBERT/多向量 Late Interaction：只在单向量与 Rerank 仍无法满足细粒度匹配时实验。
- GraphRAG：只在全局主题、跨文档关系和实体聚合数据集上证明收益后引入。
- Docling 或同类解析器：先以独立 Parser Adapter 实验 PDF、表格和版面保真，不直接替换稳定链路。

## 第一版范围

- FBA 项目初始化及基础运行配置。
- 知识库 CRUD 与访问控制。
- 文档上传、对象存储、解析、预览和删除。
- Celery 异步索引与重试。
- PostgreSQL + pgvector 向量持久化和检索。
- 可配置的 OpenAI 兼容 Embedding 与聊天模型适配器。
- PostgreSQL 全文检索、RRF 混合召回和可选重排。
- 基础 RAG 与有界 Agentic RAG 非流式问答接口。
- 查询路由、改写/拆解、证据充分性判断、引用检查和一次答案修复。
- 版本化离线评测集和质量、延迟、成本回归报告。
- 基础统计、日志、健康检查和自动化测试。

## 暂不支持

- 多轮对话、会话标题和消息历史。
- 图片、音频、视频等多模态知识解析。
- OCR 和扫描 PDF。
- Excel、PPT、网页抓取和站点爬虫。
- OCR 和扫描 PDF；扫描件或无法提取正文的 PDF 会明确失败。
- GraphRAG、知识图谱、实体关系抽取和社区摘要。
- 外部网页搜索、任意第三方工具和开放式深度研究 Agent。
- 文档版本管理和协同编辑。
- 匿名公开访问。
- 多租户计费、套餐、支付和用量结算。
- 图片生成、客服工单与情绪识别。
- 前端管理控制台。

## 产品验收标准

- 用户可完成“创建知识库 -> 上传文档 -> 等待索引 -> 检索 -> 获取带来源答案”的完整链路。
- 越权读取、修改和删除均被拒绝，且不泄露资源信息。
- 支持的文件可正确解析，空文件和不支持的格式会返回明确错误。
- 索引失败可见、可重试，重试不会产生重复数据。
- 删除知识库或文档后不能再检索到相关内容。
- 答案来源能定位到真实文档与切片。
- 上下文不足时系统明确说明，不伪造知识库内容。
- 精确术语和语义问题都能通过混合检索进入候选集，重排失败时可安全降级。
- 简单问题默认不承担 Agentic 多轮成本；复杂问题可观察到有界的拆解和自校正过程。
- Agent 达到预算或证据不足时会停止，不会无限循环或依赖模型记住停止规则。
- 文档内提示注入不能改变系统提示、工具范围、权限边界或引用结果。
- 每次发布具有可重复的基础/Agentic 对比评测报告。
